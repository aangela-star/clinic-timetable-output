# 晉安官網換圖｜Claude in Chrome 驗證型 Pilot Checklist

## 目的與範圍

這份文件只做一件事：驗證「Claude in Chrome（瀏覽器擴充功能，在使用者自己已登入的 Chrome 裡操作頁面）」能否穩定走完 `docs/JINAN_CONTROLLED_PRODUCTION_PILOT_RUNBOOK.md` 已經證明可行的換圖流程。

這不是一份新的正式發布程序，也不取代：
- 既有「受控瀏覽器 Pilot」（2026-09-06，見上述 runbook）的歷史證據與還原基準。
- 發布工作包 MVP（`jinan-publish-*.json`，尚未接 `/api/publish`、尚未登入 CMS、尚未上傳）。
- server-side adapter／login contract 的評估。

本次只回答一個問題：Claude in Chrome 這個工具本身，操作起來是否可信、是否會卡在已知的 CKEditor 陷阱（例如雙擊誤觸超連結設定）。結果只用來判斷「要不要把 Claude in Chrome 列為晉安 CMS 的 adapter 選項之一」，不自動授權任何之後的正式發布。

## 執行前必須成立的條件

- 由 Angela（或其他授權者）在**當次執行當天**明確核准：
  - 目標頁面：`https://www.tainanrehab.com/time.html`（編輯頁：`https://www.tainanrehab.com/admin/index.php?op=time&sub=set`）。
  - 來源檔案：單一已核准 PNG 的完整路徑、bytes、SHA-256。
  - 本次僅做這一張圖的置換，不擴大到其他圖片、其他頁面或毅安官網。
- 本次核准只對本次執行有效。不得因為這次成功，之後自動重複執行或排程化。
- Chrome 使用操作者自己已登入 CMS 的 session。**不要把帳號密碼貼進跟 Claude 的對話框**；登入本身由人工在瀏覽器完成，Claude in Chrome 只在已登入的頁面上操作後續步驟。
- 全程人在場監看，對每一個會改變頁面內容的動作保持可以隨時中止。

## Step 0：記錄操作前基線（不可省略）

在讓 Claude in Chrome 碰任何東西之前，先確認並記錄：

1. 開一個新分頁（或無痕視窗），匿名訪問 `https://www.tainanrehab.com/time.html`。
2. 記下目前目標 `<img>` 的 `src`、`style`（寬高）。
3. 對這張圖做一次內容核對（dimensions、bytes、SHA-256）。可以請這個 Claude Code session 用 `curl` 幫你算，不需要在 Chrome 裡做。
4. 跟核准來源比對：目前公開圖是不是上一次 Pilot 留下的已知基線（見既有 runbook「最新公開基線」表）。如果不是、或跟記錄不一致，先停下來查清楚，不要繼續。

## Step 1：請 Claude in Chrome 執行置換（逐步、每步確認）

把下面每一步拆開跟 Claude in Chrome 說，不要一次性丟整段流程要求它自動做完——每一步做完都自己看一眼畫面再放行下一步。

1. 開啟編輯頁 `https://www.tainanrehab.com/admin/index.php?op=time&sub=set`，確認畫面是晉安「門診時間表」編輯頁，不是其他頁面。
2. **單擊一次**選取目前的目標圖片。**不要雙擊**——已知雙擊會開啟「超連結」設定，改到的是外層 `<a href>`，不是真正的 `<img src>`。
3. 點 CKEditor 工具列第三行第一個「影像」／「影像屬性」圖示（不是任何跟超連結、hyperlink 相關的圖示）。
4. 在「上傳」分頁選取本次唯一核准的 PNG 來源，點「上傳至伺服器」**一次**。如果核准的衍生圖網址已經存在（例如上一次 Pilot 已經上傳過同一張），直接填那個 URL，不要重複上傳。
5. 核對「影像資訊」裡的 URL、寬度、高度是預期值，其他屬性不要動，點右下角綠色「確定」。**這一步只套用到編輯器裡，整頁還沒送出。**
6. 用 CKEditor「原始碼」檢視，確認只有目標 `<img src>` 變了，其他 HTML、`<a href>`、其他圖片、文字、SEO 欄位都沒變，再切回編輯模式。
7. 捲到整頁最下方「訊息確認」區域，點真正的「送出」按鈕**一次**。「訊息確認」這個標題文字本身不是送出按鈕，不要點錯。
8. 送出後畫面會回到 `op=time&sub=set&mesCode=1` 之類的回應頁——這只是提交回應，**不等於已公開驗證成功**，也不要因為看到這個就再送一次。

## Step 2：送出後的公開驗證（獨立於 CMS session 之外）

1. 用跟 Step 0 一樣的方式，開新分頁或無痕視窗，匿名重新 GET `https://www.tainanrehab.com/time.html`。
2. 確認目標 `<img>` 的 `src` 已經指向本次核准來源對應的 CMS 衍生圖 URL，寬高跟預期一致。
3. 匿名 GET 這個圖片 URL 本身，核對 dimensions、bytes、SHA-256 跟「送出前已經驗證過的衍生圖」完全一致。
4. 用完整公開 HTML 跟 Step 0 的備份比對，確認只有目標 `src` 改變，其他內容、其他圖片、連結都沒被動到。
5. 只有這四項都核對一致，才算這次置換驗證成功。CMS 顯示「成功」訊息、網址有變、或 HTTP 200，都不能單獨當作驗證通過。

## 中止條件

遇到以下任何一種情況，立刻停止，不要重試、不要重新上傳、不要自己猜測原因後繼續：

- Step 0 記錄的基線跟既有 runbook 的「最新公開基線」不一致（可能有人在這之間動過）。
- Claude in Chrome 在任何一步回報它不確定剛剛的點擊生效與否。
- 雙擊誤觸、跳出非預期的超連結設定視窗，或任何畫面跟本文件描述的流程不符。
- 送出後的公開驗證（Step 2）四項任一項不一致。
- 過程中介面要求輸入帳號密碼，而操作者沒有親自在瀏覽器輸入。

中止後只做唯讀查證（重新 GET 公開頁、比對 hash），不做任何還原或重送，等人工確認現況後再決定下一步。

## 本次結果應該回答的問題

跑完一次之後，把下面幾點記下來（不需要寫進這份 checklist 本身，可以另外記錄或回來跟我說）：

1. 全程有沒有卡在雙擊/超連結這個已知陷阱、或其他 UI 誤觸。
2. Claude in Chrome 對「單擊選取圖片」「點影像屬性圖示」這類精細操作的辨識穩不穠。
3. 公開驗證（Step 2）四項是否一次就對齊，不需要人工介入修正。
4. 跟既有「受控瀏覽器 Pilot」（2026-09-06）比較，操作步數、出錯機率、人工介入程度誰更低。

這四個答案決定晉安 CMS 的 browser automation adapter 要不要往 Claude in Chrome 這個方向定案，而不是本文件本身的通過與否。
